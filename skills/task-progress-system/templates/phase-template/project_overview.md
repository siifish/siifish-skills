## 维护约定

| 层级 | 文档 | 内容 | 更新时机 |
|---|---|---|---|
| L1 | `project_overview.md` | 摘要、看板、Exit Criteria、当前判断 | 任务状态或路线变化时 |
| L2 | `tasks/*.md` | 单任务步骤、执行记录、结果、失败征兆 | 执行 / 出结果时 |
| L3 | `changelog.md` | 已发生事件流水 | 完成实质工作后 |
| L3 | `handoff.md` | 接手指南、决策图、任务速查 | 执行顺序或路线变化时 |
| L3 | `reference.md` | 命令、路径、配置完整参考 | 命令 / 路径 / 产出变化时 |

维护规则：

1. L1 只写结论、数字、状态和缺口，详细分析放 L2/L3。
2. 完成任务：先补 task 执行记录，再改 overview 状态，最后追加 changelog。
3. 新增任务：看板加行，`tasks/` 建文档，更新 Exit Criteria 和外部索引。
4. 新增长报告或脚本：放 `resources/`，并在相关 task 或 overview 中链接。
