# Flomo Manager

将您的灵感和思考转化为结构化的 flomo 笔记。

## 触发方式

以下任一方式触发：

- `/flomo` 或 `FM` 或 `发送到 flomo` 或 `调用 flomo manager`

## 工作流程

用户输入一段灵感后，Flomo Manager 按以下步骤把“零散想法”变成可发送的结构化笔记：

### Step 1：初始化检查

- 检查本地缓存是否存在。
- 若缓存不存在：显示“正在初始化缓存...”，并拉取标签树。

### Step 2：关键词提取

- 自动提取 2-4 个核心关键词。
- 将关键词展示给用户，用于确认或修改。

### Step 3：检索相关笔记

- 使用 `memo_search` 检索相关笔记。
- 最多获取 5 条相关笔记。
- 基于相关笔记分析其风格特征（用于后续写作匹配）。

### Step 4：撰写笔记

- 参考相关笔记长度，将正文控制在 800-1200 字左右。
- 采用与相关笔记匹配的格式与风格。
- 如果用户给的是一个灵感，你要根据情况适当扩写一下。
- 输出内容包含：标题 + 自然段，对关键概念进行 **加粗**标注或者划线，也可以用列表格式。
- 添加关联笔记链接（完整格式）。
- 综合相关笔记与标签树，推荐 3-5 个标签。

### Step 5：展示并确认

- 向用户展示：
  - 提取的关键词
  - 检索到的相关笔记摘要
  - 撰写的笔记内容
  - 推荐的标签
- 等待用户确认或提出修改意见。

### Step 6：发送或修改

- 用户说“发送”：推送到 flomo。
- 用户说“修改”：根据反馈重新撰写。
- 同步更新本地记忆（偏好的标签、风格调整）。

## 缓存系统

### 缓存文件

```
skills/flomo-manager/cache/
├── tag_tree.json              # 完整标签树
├── tag_semantics.json         # 标签语义理解（每个标签的含义、使用场景、代表性笔记）
├── tag_stats.json             # 标签使用统计（笔记数量、最近使用时间、使用趋势）
├── recent_notes.json          # 最近20条笔记（用于风格分析）
├── style_profile.json         # 风格特征总结
├── user_preferences.json      # 用户偏好（常用标签、风格调整）
├── walk_history.json          # 漫步洞察积累（历次漫步的发现和统计）
└── last_update.txt            # 上次更新时间
```

### 缓存更新

- **定时更新**：每日首次使用时自动刷新
- **手动更新**：用户说"更新 flomo 缓存"或"重建标签缓存"
- **漫步增量更新**：漫步过程中，每读一批笔记自动增量更新 `tag_semantics` 和 `tag_stats` 中涉及到的标签
- **漫步结束更新**：漫步结束时将本次发现的 observations 追加到 `tag_semantics.system_observations`，更新 `walk_history`
- **全量语义扫描**：用户说"重建标签缓存"时，遍历 `tag_tree` 的所有标签，对每个标签搜索 1-2 条代表性笔记推断语义描述

### 冷启动

首次使用时显示："正在初始化缓存，请稍候..."，然后拉取标签树和最近笔记。若标签语义缓存不存在，自动基于标签名和层级结构推断初始语义。

### 漫步相关 API 使用映射

| 分析需求 | 调用的 API | 说明 |
|---|---|---|
| 加载标签体系 | `tag_tree` | 获取完整标签层级结构 |
| 搜索标签 | `tag_search` | 在标签数量很多时快速定位 |
| 发现笔记关联 | `memo_recommended` | 基于某条笔记获取系统推荐的关联 |
| 批量读取笔记 | `memo_batch_get` | 按 id 列表获取笔记全文（单次最多 50 条） |
| 修改笔记标签/内容 | `memo_update` | 用户确认后执行 |
| 批量重命名标签 | `tag_rename` | 合并重复标签 |
| 获取用户画像 | `memory_user` / `memory_context` | 辅助理解用户的标签使用习惯 |

## 记忆功能

### 记录的内容

1. **偏好的标签**：用户经常选择或手动添加的标签
2. **风格调整**：用户对自动生成笔记的修改模式
3. **标签关联**：某些主题下用户偏好的标签组合

### 记忆应用

- 推荐标签时优先显示偏好标签
- 撰写时参考历史风格调整

## 错误处理

### 检索失败

- 及时反馈用户
- 尝试使用备用策略（如仅关键词匹配）
- 与用户沟通解决方案

### 发送失败

- 反馈错误信息
- 保留笔记内容，询问是否重试
- 提供手动复制选项

## 并发处理

支持并行处理多条灵感，按顺序向用户展示结果。

## 智能漫步

在 flomo 笔记中自由探索，以主题为单位阅读和复习笔记。漫步过程中同时分析笔记内容、标签使用和笔记关联，提出优化建议，并边走边学维护标签语义缓存。

### 触发方式

- `/flomo walk` 或 `flomo 漫步` 或 `随机漫步` 或 `漫步 flomo`
- **无主题入口**：直接说`随机开始`或`帮我选一个主题`
- **标签分析入口**：说`看看标签体系`或`标签分析`（加载缓存直接输出标签体系概览和优化建议，不进入漫步）

### 核心交互模式

每次交互分三个阶段：**初始化**、**漫步（含分析）** 和 **深入**。

```
用户触发（输入主题 或 无主题）
    ↓
【初始化】
加载标签缓存（tag_tree + tag_semantics + tag_stats）
    ↓
【漫步阶段】
搜索主题相关笔记 → 阅读+分组 → 分析（标签/关联/内容） → 输出综述+内嵌优化建议
    ↓
四选一：[深入某个子主题 / 执行优化建议 / 换个子主题 / 换主题]
    ↓
【深入阶段】（用户选了某个子主题）
用子主题关键词重新搜索 → 阅读+分析 → 输出扩展综述+内嵌建议
    ↓
四选一：[继续深入 / 执行优化建议 / 回到主主题 / 换主题]
    ↓
【结束漫步】
漫步总结（已执行优化 + 未处理建议 + 标签体系健康度） → 缓存更新
```

### Step 0：初始化缓存加载

漫步开始时自动加载缓存（不对用户展示中间过程）：

1. 加载 `cache/tag_tree.json`（标签树结构）
2. 加载 `cache/tag_semantics.json`（标签语义理解）
3. 加载 `cache/tag_stats.json`（标签使用统计）
4. 若缓存不存在或 `last_update.txt` 超过 7 天：
   - 调用 `tag_tree` API 拉取完整标签树
   - 基于标签名和层级结构推断初始语义（写入 `tag_semantics.json`）
   - 显示"正在初始化标签缓存..."

### Step 1：入口判断

**有主题**（用户说了具体词）
- 直接用该关键词搜索：`memo_search(keywords=用户输入, limit=10)`

**无主题**（用户说`随机开始`或`帮我选`）
- 调用 `get_daily_review()` 尝鲜每日回顾
- 有内容 → 告知用户，以此为主题开始
- 无内容 → 我从近期笔记标签中挑选 3 个不同领域的主题候选，展示给用户选择

**主题候选池生成方式**：
1. 调用 `tag_tree` 获取全部标签
2. 挑选 3 个不同领域方向的标签作为候选（如：一个科研方向、一个生活/经验类、一个工具/方法类）
3. 展示给用户：`主题 A / 主题 B / 主题 C`
4. 用户说`换一批` → 重新挑 3 个不同方向的候选
5. 用户选哪个 → 用该关键词进入漫步

### Step 2：搜索 & 过滤

```bash
npx mcporter call flomo.memo_search --config config/mcporter.json --args '{"keywords":"主题关键词","limit":10}'
```

**过滤规则**：
- 剔除 `word_count < 80` 的短笔记（大多是 TODO/Inbox）
- 剔除标签含 `#TODO` 的笔记
- 剩余笔记按 `relevance` 降序排列

### Step 3：阅读 & 分组

我需要完成以下工作（不对用户展示中间过程）：

1. **通读**全部通过过滤的笔记
2. **按子主题分组**：把内容相近的笔记归到同一小节
3. **提炼每个子主题的核心要点**：不是简单罗列笔记，而是综合多篇笔记形成连贯的综述
4. **决定展示顺序**：最核心的子主题放前面

### Step 3.5：分析层（内部处理，不展示中间过程）

对每组笔记执行三个维度的分析：

**维度 A：标签分析**

结合已加载的 `tag_semantics` 和 `tag_stats` 缓存：

- **缺失标签**：笔记内容明显属于某个已有标签但未打上（如笔记讨论了 VLA 模型但没有 `#领域路线/VLA` 标签）
- **多余标签**：标签与笔记内容不匹配
- **不精确标签**：可以替换为更精确的子标签（如 `#AI` 过于宽泛，应替换为 `#领域路线/具身智能`）
- **跨笔记一致性**：同一子主题下的笔记标签是否一致，同类内容是否使用了不同的标签

**维度 B：关联发现**

- 对每个子主题中的关键笔记（relevance 最高的 1-2 条），调用 `memo_recommended` API 获取系统推荐的关联笔记
- 对比当前搜索结果中的笔记，发现已有笔记之间未建立但应该建立的连接
- 识别跨子主题的笔记关联（如子主题 A 的某条笔记与子主题 B 的某条笔记讨论了同一论文的不同角度）

**维度 C：内容质量**

- 识别高度相似/重复的笔记，建议合并
- 识别内容可以互相补充的笔记（如一条是概述，另一条是细节，合并后更完整）
- 识别观点有更新但旧笔记未同步的情况（如旧笔记的结论已被新笔记推翻）

**维度 D：标签体系观察（全局视角）**

基于本轮遍历到的标签和缓存中的全量标签体系，识别：

- **重复标签候选**：两个标签含义高度重叠（如 `#VLA模型` 与 `#领域路线/VLA`），建议合并
- **新标签建议**：多条笔记涉及某个主题但缺少专门标签，建议新建子标签
- **低频标签预警**：使用频率极低（<3 条笔记）的标签，考虑是否需要保留或合并到父标签
- **层级优化**：标签层级结构是否合理，是否有标签应该提升/降级

**分析时的缓存维护（边走边学）**：

- 每分析一批笔记，增量更新 `tag_semantics` 中涉及到的标签语义（若缓存中该标签的 `confidence` 为 `low`，根据本次看到的笔记内容补全 `description` 和 `usage_scenario`）
- 增量更新 `tag_stats` 中涉及到的标签统计数据
- 新发现的 observations（重复标签、新标签建议等）暂存在 `walk_state.tag_observations` 中，漫步结束时一次性写入缓存

### Step 4：输出主题综述（内嵌优化建议）

格式：

```

- 🏷️ 标签 | 笔记2 的 #AI 过于宽泛，建议替换为 #领域路线/具身智能
- 🔗 关联 | 笔记1 与笔记3 讨论了同一论文的不同角度，建议建立双链

...
```

### 错误处理

- **搜索结果为空**：提示"这个主题暂时没有找到笔记，要换一个吗？"，退回 Step 1
- **所有笔记都被过滤**：提示"相关笔记太少了，试试别的关键词？"
- **MCP 调用失败**：提示用户稍后重试，保留当前状态
- **标签缓存不存在**：自动触发冷启动初始化（Step 0）
- **优化建议执行失败**：反馈错误信息，保留建议列表，询问是否重试或跳过
