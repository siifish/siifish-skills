# 笔记模板

> 风格基准：`2026-09-08 📑 Fast-WAM`（Bear 笔记 id `CBE4425F-1454-4740-A733-9ED3F1B432F4`），写作前先 cat 它对照一遍。

## 通用骨架

```markdown
# <标题由 bearcli create 的标题参数承载，正文不写 # 标题>

#Notes/读论文/摘要 #TODO/unread   ← 数据集类换成 #Notes/读论文/数据集 #TODO/unread

- arXiv:<v1日期> | <机构1>、<机构2>
- [<论文全名>](<abs页链接>)
- 项目主页：[<名>](<url>)；代码：[<repo>](<url>)
- ***Reading Log***
  - <一句话概括：做了什么 + 核心结论>

## <五节之一>
...
```

- 发表信息：arXiv 论文写 `arXiv:YYYY-MM-DD`；已录用写 `ICLR 2027 | <机构>`。
- 项目主页/代码行：没有就省略整行。
- Reading Log 只写一条一句话概括；用户的个人批注（如 `#项目/...` 链接）由用户自己加。

## 方法类五节

### `## 背景相关工作问题`
- 领域现状 → 现有两条技术路线（列名 + 一句话各）→ 它们的具体问题。
- 用 `**加粗**` 标术语，结尾 `~研究问题一句话概括~`。

### `## 思路贡献`
- 编号列出 3~5 条贡献，每条先 🟢/🟡/🔵 标极关键项，再一句话展开。
- 结尾 `~设计本质一句话~`。

### `## 方法细节`
- 按论文结构拆 2~5 个 `### 子节`，公式用 `$...$` / `$$...$$`。
- 具体数字必写（参数量、horizon、hidden dim、学习率、去噪步数等）。
- 方法总览图放第一节末尾。

### `## 数据集任务、验证指标、对比Baseline和算力`
- 数据集与任务：规模、任务数、训练 steps、评测 trials。
- 验证指标：名称 + 是否报告了方差/置信区间。
- Baseline：分类列出（同期方法 / 经典方法 / 自家消融）。
- 模型、超参数与算力：**未报告的明确写"未报告"**（如训练 GPU 小时、λ）。

### `## 实验结果`
- 按数据集/实验分 `### 子节`，关键数字**复读**（91.8 vs 90.6 这种对比要写出来）。
- 表/图截图附在对应小节末尾。
- 收尾 `### 结论与局限`：真正的贡献是什么 + 边界条件（任务范围、未披露的统计、复现缺口）。

## 数据集/基准类五节

### `## 背景与动机`
现有数据为什么不够、本文补什么缺口。

### `## 数据构建流程`
采集/标注/清洗流水线，规模化的关键设计，质量控制。

### `## 数据规模与分布统计`
条数、时长/Token 数、类别分布、与已有数据集的对比表（附截图）。

### `## 基准任务与评测协议`
基于该数据定义的下游任务、评测指标、leaderboard 设置。

### `## 实验结果与发现`
基线在其上的结果、关键发现、数据规模/质量消融、局限与伦理考量。

## 速读版

用户说"速读"时：保留开头信息块，五节各压到 2~4 句，砍 `### 子节`、砍局限讨论、砍附图（最多留 1 张方法图）。

## 公式规则

- 行内公式：`$...$`。
- **行间公式必须写成三行**（`$$` 单独成行，公式一行，`$$` 单独成行）——`$$...$$` 单行写法在 Bear 里不渲染：
  ```
  $$
  R' = R \oplus (t - t_{prev})
  $$
  ```

## 写作红线

- 关键数字必须复读，不写"效果显著"这种空话。
- 论文没报告的如实说，不编。
- 不复制论文 abstract 当总结，takeaway 用自己的话。
- 公式中的 LaTeX 注意 Bear 兼容性：避免 `\mathbb` 之外的重型宏包，`\mid`、`\qquad`、`\mathcal` 可用。
